1. Между программой и оборудованием всегда стоит посредник —
операционная система, и именно она управляет доступом
к процессору, памяти, файлам. 
.NET предоставляет программе готовые средства для получения сведений о
текущем компьютере, процессе и операционной системе.
2. Когда программа запускается, операционная система создаёт для неё процесс -- отдельное окружение со своей памятью. 
3. 64-битная ОС -- это современный тип программного обеспечения, которое обрабатывает данные блоками размером 64 бита (8 байт) за один цикл и способно эффективно работать с большим объемом оперативной памяти.
4. Environment.ProcessorCount показывает количество логических процессов, но оно не будет совпадать с числом физических ядер всегда.
5. Working Set лишь небольшая часть физической оперативной памяти (ОЗУ) компьютера, которую операционная система в данный момент выделяет конкретной программе.
6. Потому что содержимое компьютера к компьютеру может всегда отличаться, как ОС так и процессор. 

Я понял эту трехслойную архитектуру, она позволяет компьютеру функционировать. 
Первый слой: сначала есть программа с которой взаимодействует пользователь. Она ничего не знает о нашем компьютере, а для того чтобы узнать эту информацию она обращается к операционной системе.
Второй слой: операционная система компьютера, она предоставляет единый интерфейс нашим программам, распределяет ресурсы нашего железа, то есть оперативную память и процессорное время, и следит за тем чтобы программы друг другу не мешали выполнять работу.
Третий слой: компьютер, физическая основа: процессор, видеокарта, жесткие диски, ОЗУ. Железо понимает лишь простейший машинный код. От ОС железо получает огромный поток инструкций для выполнения, сложить числа или передать память, и выполняет их с гигантской скоростью.
Таким образом, программе не обязятельно на прямую знать что-то о железе чтобы выполнить задачу, всю информацию и задачи передает простая понятная ОС. И именно поэтому мы получаем нужные нам названия железа именно через ОС.
